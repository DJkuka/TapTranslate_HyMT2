# Tap Translate 1.125 FontFit/AutoFill + Hy-MT2 Offline

## ВАЖНО: правильная исходная версия APK

Этот проект пересобирается **на основе пользовательского файла** `TapTranslate_1.125_FontFit_AutoFill_unsigned.apk`, а не предыдущего `TapTranslate_1.125_Tesseract551_EnglishOCR_unsigned.apk`.

SHA-256 исходной базы:

```text
3cc9ac5a10add494b2053b947a8c748c7f0c2f5c69e936216a5ef1df4c833910
```

Workflow проверяет этот хеш до сборки. Если вместо него окажется другой APK, сборка остановится.

### Восстановление английского Tesseract OCR

В прежнем APK `Tesseract551_EnglishOCR` английское распознавание уже было переведено на Tesseract, но вместе с этим туда попали посторонние изменения механизма Google Offline Translate. В этом проекте восстановлены только необходимые для английского OCR изменения, а проблемные изменения переводчика не переносятся.

- `qh/p.smali`: `English` добавлен в существующий набор языков Tesseract. Благодаря этому штатный обработчик выбора языка запускает штатную загрузку `eng.traineddata` через существующий загрузчик приложения.
- `x9/e.smali`: для английского Tesseract инициализируется кодом модели `eng`, а не составным `eng+eng`.
- `vh/j.smali`: основной маршрут OCR явно направляет английский в Tesseract, когда файл `eng.traineddata` уже существует. Вторичный маршрут также проверяет модель. Пока файл не загружен, приложение использует исходный Google VisionKit/ML Kit OCR, а не пытается запустить Tesseract без данных.
- Исходная `lib/arm64-v8a/libtesseract.so` сохраняется без изменений.

Остальные языки не перенаправляются на английскую модель и сохраняют прежнее поведение. Для Google Offline Translate сохраняются исходный выбор пакета `PKG_LOW`, оба пакета `PKG_LOW` и `PKG_HIGH` в metadata и исходная реализация метода `yh/f->e`. Из предыдущего Tesseract APK не переносятся изменение `si/a.smali` на `PKG_HIGH`, экспериментальный пакетный перевод `yh/f->e` и удаление `PKG_LOW`.

Скрипт сборки проверяет, что английский зарегистрирован в наборе загрузки, загрузчик использует `eng`, основной OCR-маршрут проверяет наличие модели и вызывает Tesseract, а резервный маршрут остаётся доступным. Отдельно контролируются неизменность Google Offline Translate и совпадение оригинальных `assets/`, `lib/` и metadata с базовым APK.

## Что добавляет Hy-MT2

- Отдельный движок `Hy-MT2 Offline` в штатном выборе переводчиков.
- Отдельный пункт настроек `Hy-MT2 Offline · GGUF model settings`.
- Выбор GGUF-файла через Android SAF.
- Прямое чтение исходного файла с SD/внешнего носителя без создания второй копии.
- CPU/NEON llama.cpp runtime для ARM64.
- Google Offline Translate остаётся резервным движком при ошибке Hy-MT2.

Модель не включается в APK. Поддерживаемая модель: `Hy-MT2-1.8B-Q4_K_M.gguf` из репозитория Tencent:

https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF

### Прямой SAF без копирования

Приложение сохраняет SAF URI и persistable read permission, открывает `ParcelFileDescriptor` и передаёт llama.cpp путь `/proc/self/fd/N`. Дескриптор остаётся открытым, пока модель загружена. Дополнительная копия примерно на 1,13 ГБ не создаётся.

Перед использованием проверяются тип обычного файла, размер, сигнатура GGUF и повторное открытие proc-fd. Конкретный DocumentsProvider должен предоставлять обычный seekable file descriptor; если он возвращает поток/pipe, приложение сообщает об этом и не копирует файл скрытно. Успешный probe сам по себе не гарантирует, что native `mmap` сработает на любом провайдере; окончательная проверка — успешная загрузка и перевод с SD-карты на планшете.

Старые копии, созданные прежними версиями, не используются автоматически и не удаляются. После успешной проверки их можно удалить вручную из `Android/data/com.tap_to_translate.snap_translate/files/models/`, если они там остались.

## Настройки Hy-MT2

### Производительность

- Профили: «Быстрый», «Сбалансированный», «Качественный», «Настраиваемый».
- CPU threads: 2/3/4/6/8 (ограничивается доступными ядрами).
- Context size: 2048/3072/4096/6144/8192 токенов.
- Max output tokens: 256–4096.
- Temperature, Top-P, Top-K.
- Статистика скорости `tokensPerSecond`, длительности и среднего значения последних десяти успешных переводов.

Для Snapdragon 680 начни с профиля «Сбалансированный» (контекст 2048). Значения 6144–8192 могут резко увеличить потребление RAM и вызвать OOM. Изменение загрузочных параметров требует выгрузить и загрузить модель заново.

### Контекст и терминология

- Фоновое описание мира, персонажей и ситуации.
- Словарь формата `Original = Translation`.
- 0–4 предыдущих пары «оригинал → перевод» как контекст.
- История хранится в памяти, разделяется по языковой паре, автоматически устаревает через три минуты и очищается вручную.

### Стиль

- Естественный перевод комиксов.
- Разговорный и живой язык.
- Более дословный перевод.
- Драматичный стиль, ирония и сарказм.
- Свой стиль с пользовательскими инструкциями.

Эти параметры формируют запрос к модели; слишком длинный контекст тоже увеличивает время генерации.

### Таймер

В текущем runtime нет таймера, который принудительно отменяет локальную генерацию. `maxTokens` задаёт длину вывода, а не время.

### Vulkan

Переключатель Vulkan вынесен отдельно, но заблокирован в этой CPU/NEON-сборке. Наличие Vulkan 1.1 у Adreno 610 не означает, что используемая библиотека llama.cpp собрана с Vulkan backend. Для включения понадобится отдельная сборка native runtime и проверка на устройстве. CPU-режим остаётся доступным и не подменяется.

## Сборка через GitHub Actions

1. Распакуй архив проекта.
2. Загрузи **содержимое** папки `TapTranslate_HyMT2_Integration` в корень GitHub-репозитория, сохранив `.github/workflows`, `app`, `input`, `scripts`, `tools`.
3. Убедись, что в `input/` лежит `TapTranslate_1.125_FontFit_AutoFill_unsigned.apk`.
4. Commit в `main`.
5. Actions → `Build Tap Translate 1.125 FontFit AutoFill + Hy-MT2` → `Run workflow`.
6. Скачай Artifact `TapTranslate-1.125-FontFit-AutoFill-HyMT2-unsigned`.

Workflow использует JDK 17, Android SDK setup v4, compileSdk 35 и Gradle 8.9. Сначала проверяет SHA-256 базы, наличие обоих Offline Translate model packages и Tesseract native library; затем компилирует helper APK, объединяет Hy-MT2 runtime с исходным APK через apktool, выравнивает и проверяет итоговый unsigned APK.

## Что проверить на планшете

1. Подпиши APK тем же тестовым ключом, которым подписываешь предыдущую версию.
2. Выбери `English` как исходный язык OCR. При отсутствии файла модель должна скачаться штатным диалогом приложения. Файл должен появиться в `tessdata` под именем `eng.traineddata`.
3. После завершения загрузки запусти OCR английской страницы. В logcat ищи тег `TT_OCR` и сообщение `English Tesseract route active; eng.traineddata present`. Это подтверждает не просто наличие файла, а фактический выбор Tesseract в основном маршруте распознавания.
4. Проверь ещё один язык, для которого Tesseract уже работал, чтобы убедиться, что его маршрут не изменился.
5. Выбери `Hy-MT2 Offline`, укажи исходный GGUF на SD-карте и загрузи модель; проверь короткий перевод и несколько реплик с включённым контекстом.

Если английская модель не начинает скачиваться, пришли лог с момента выбора языка и тегами `TT_OCR`, `path` и `AndroidRuntime`. Если модель скачалась, но распознавание не использует Tesseract, нужен logcat с тегом `TT_OCR` во время OCR.

## Степень проверки

- Проверен SHA-256 именно пользовательской базы.
- Apktool декодировал эту базу; все патч-anchors найдены ровно один раз.
- Все функции интеграции применены на отдельной копии декодированной базы.
- Английский Tesseract patch отдельно применён и прошёл проверку структуры: English зарегистрирован для загрузки, `x9/e` инициализирует `eng`, основной OCR-маршрут выбирает Tesseract только при наличии `eng.traineddata`.
- Проверено, что резервный OCR остаётся доступен, а исходный код Google Offline Translate не изменён.
- Проверен Python-синтаксис merge-скрипта и base verifier.
- Полная Gradle-сборка helper + merge и runtime-тест на планшете выполняются после запуска GitHub Actions. До этого готовый APK не считается собранным.
